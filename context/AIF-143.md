# Corporate Learning AI Customer Journey Orchestrator

## Objective

Design and develop an AI-powered **AI Customer Journey Orchestrator** for a **Enterprise L&D team** operating in the **Corporate Learning** industry.

The organisation currently faces this problem: **Customer interactions are fragmented across channels, leading to inconsistent follow-up**.

The objective is to unify customer data and coordinate personalised next-best actions across channels. The system must support skill assessment, learning-path assignment, course delivery, practice, assessment, coaching, certification, and workforce planning. It must provide a reliable operational view across employees, managers, instructors, learning administrators, HR partners, and business leaders. AI must act as a decision-support capability, with authorised users retaining control over material actions.

## Requirements

### 1. Frontend Requirements

- Create a unified profile and interaction timeline for the relevant customers among employees, managers, instructors, learning administrators, HR partners, and business leaders.
- Display journey stages across skill assessment, learning-path assignment, course delivery, practice, assessment, coaching, certification, and workforce planning, including open requests, transactions, communications, consent, and service history.
- Provide segment builders, campaign or outreach configuration, next-best-action cards, channel preferences, frequency controls, and agent work queues.
- Include service tickets, conversation history, AI-drafted responses, churn or propensity indicators, outcome tracking, and journey analytics.
- Provide secure sign-in, role-aware navigation, responsive layouts, loading states, validation messages, and accessible controls.
- Display domain data for employees, managers, instructors, learning administrators, HR partners, and business leaders without exposing records outside the signed-in user’s permissions.
- Include global search, filtering, sorting, pagination, saved views, notifications, and export where appropriate.
- Show AI outputs with source data, confidence, explanation, timestamp, model/version information, and a clear approve, reject, or override action for authorised users.

### 2. Backend Requirements

- Build APIs for profile unification, identity matching, consent and preference management, interaction history, segmentation, service tickets, campaigns, and message delivery.
- Integrate approved email, SMS, messaging, web, or call-centre channels and record delivery, response, opt-out, and outcome events.
- Run churn, propensity, intent, and next-best-action scoring, then enforce eligibility, consent, frequency caps, and approval rules before outreach.
- Support agent-assist response generation, conversation summarisation, feedback capture, and closed-loop outcome measurement.
- Expose versioned REST APIs with request validation, structured errors, pagination, filtering, idempotency for critical writes, and API documentation.
- Implement secure authentication, role and permission checks, tenant or organisation isolation, audit-event creation, and configuration management.
- Support background jobs, notifications, scheduled processing, retries, dead-letter handling where needed, observability, and health checks.
- Maintain a human-review workflow for high-impact AI recommendations and record input data, output, confidence, reviewer decision, override reason, and model version.

### 3. Database Requirements

- Model the core domain entities: employees, roles, skills, courses, enrolments, progress, assessments, certifications, opportunities, and audits.
- Include unified profiles, identity links, consent and preferences, interactions, channels, segments, journeys, campaigns, offers, recommendations, messages, tickets, outcomes, and opt-out events.
- Use UUID or similarly safe identifiers, foreign keys, uniqueness rules, status enums, created and updated timestamps, soft deletion where justified, and optimistic concurrency for frequently edited records.
- Create separate tables or collections for users, roles, permissions, organisations or tenants, notifications, comments, attachments, configuration, model versions, AI runs, approvals, overrides, and audit logs.
- Store large documents and media in object storage and keep metadata, checksums, ownership, access policy, version, and storage reference in the database.
- Add indexes for common filters, search, dates, status, organisation, relationship keys, and dashboard aggregations; define retention and archival policies for historical data.

### 4. AI Requirements

- Implement the specified AI capabilities: intent classification, churn and propensity prediction, next-best-action recommendation, response drafting, conversation summarisation.
- Classify intent and sentiment, summarise interactions, estimate churn or conversion propensity, recommend the next best action, and draft channel-appropriate responses.
- Use the profile, consent, interaction history, and outcomes from skill assessment, learning-path assignment, course delivery, practice, assessment, coaching, certification, and workforce planning while excluding prohibited attributes and respecting frequency and eligibility rules.
- Measure recommendation acceptance, customer response, conversion, retention, false positives, and segment fairness; support feedback and model recalibration.
- Define training and evaluation data boundaries, offline evaluation metrics, acceptance thresholds, bias or safety tests where relevant, and production monitoring for accuracy, drift, latency, and failures.
- Do not expose hidden chain-of-thought. Provide concise user-facing explanations based on observable inputs, rules, model factors, and cited evidence.
- Allow authorised users to correct outputs, capture feedback, override recommendations, and trace each output to its model version and input snapshot.

### 5. User Role Requirements

- **Customer, Service Agent, Marketing Manager, Sales Manager, Admin:** manage users, roles, master data, configuration, security policies, integrations, and audit access.

### 6. Security Requirements

- Implement least-privilege role-based access, secure password hashing or enterprise identity integration, short-lived sessions or tokens, MFA support for privileged roles, and server-side permission enforcement.
- Encrypt data in transit and at rest, protect secrets, validate and sanitise inputs, scan uploads, rate-limit sensitive endpoints, and prevent common web and API vulnerabilities.
- Apply domain controls for employee privacy, fair recommendations, accessibility, content rights, retention, and audits.
- Maintain append-only audit events for login, data access, creation, modification, deletion, export, AI execution, approval, rejection, override, and configuration changes.
- Define backup, restore, disaster recovery, data-retention, deletion, legal-hold where applicable, incident response, and security-monitoring procedures.
- Apply the project-specific safety controls: consent enforcement, bias monitoring, message approval, frequency caps, secure secrets.

## Expected Output

Develop and deliver the following fully functional, responsive application pages for the **Enterprise L&D team**.

### 1. Secure Login Page

- Provide email and password fields, show/hide password, input validation, remember-me option, and forgot-password flow.
- Authenticate users using JSON Web Tokens and redirect them to the correct dashboard based on their role.
- Display clear loading, success, validation, and authentication-error states.

### 2. Unified Customer Profile Page

- Create a unified profile and interaction timeline for the relevant customers among employees, managers, instructors, learning administrators, HR partners, and business leaders.
- Present the most important status indicators, trends, exceptions, and actions in a role-aware dashboard.
- Support relevant date, location, category, owner, status, and risk filters.

### 3. Journey Timeline and Service History Page

- Display journey stages across skill assessment, learning-path assignment, course delivery, practice, assessment, coaching, certification, and workforce planning, including open requests, transactions, communications, consent, and service history.
- Provide search, filtering, sorting, pagination, record details, linked records, and version or activity history where applicable.
- Restrict records and actions according to the signed-in user's role and permitted organisational scope.

### 4. Segments, Outreach and Next-Best Actions Page

- Provide segment builders, campaign or outreach configuration, next-best-action cards, channel preferences, frequency controls, and agent work queues.
- Display clear states for normal, warning, critical, pending-review, approved, rejected, and completed items as applicable.
- Allow users to drill down from summaries into the underlying records and supporting evidence.

### 5. Service Tickets and Agent Assist Page

- Include service tickets, conversation history, AI-drafted responses, churn or propensity indicators, outcome tracking, and journey analytics.
- Provide authorised create, assign, edit, approve, reject, defer, override, escalate, and close actions where relevant.
- Record the actor, timestamp, reason, previous value, new value, and outcome for every material decision.

### 6. Intent, Sentiment and Propensity Predictions Page

- Classify intent and sentiment, summarise interactions, estimate churn or conversion propensity, recommend the next best action, and draft channel-appropriate responses.
- Show the result, confidence score, contributing inputs, explanation, timestamp, model version, and source-data snapshot.
- Provide loading, unavailable-model, insufficient-data, low-confidence, and failed-prediction states.

### 7. Consent-Aware Recommendations Page

- Use the profile, consent, interaction history, and outcomes from skill assessment, learning-path assignment, course delivery, practice, assessment, coaching, certification, and workforce planning while excluding prohibited attributes and respecting frequency and eligibility rules.
- Clearly separate AI suggestions from approved business decisions.
- Allow authorised reviewers to accept, reject, correct, or override an AI output and record a mandatory reason.

### 8. Journey Outcomes and Model Feedback Page

- Measure recommendation acceptance, customer response, conversion, retention, false positives, and segment fairness; support feedback and model recalibration.
- Compare recommendations and predictions with actual outcomes and capture user feedback.
- Display quality, accuracy, drift, latency, failure, and adoption indicators appropriate to the project.

### 9. Reports and Analytics Page

- Provide reports and visual analysis covering: a unified customer profile and omnichannel interaction timeline. consent-aware segmentation and journey management. intent, churn, propensity, and next-best-action predictions. agent-assist summaries and message drafts with approval controls. journey, campaign, service, conversion, and retention analytics.
- Include date ranges, comparison periods, relevant business filters, drill-down views, and saved report configurations.
- Allow authorised users to export filtered reports in CSV or PDF format.
- Display report-generation status and a history of generated reports.

### 10. Notifications Page and Panel

- Provide an in-app notification panel and a complete notifications page for assignments, exceptions, approvals, alerts, due dates, AI results, and system events.
- Show unread, read, urgent, assigned, and system-generated notifications.
- Allow users to mark notifications as read, clear selected notifications, and open the related record.
- Support notification preferences based on role, event type, severity, ownership, and organisational scope.

### 11. User and Role Management Page

- Support the project roles defined for this assignment: **Customer, Service Agent, Marketing Manager, Sales Manager, Admin:** manage users, roles, master data, configuration, security policies, integrations, and audit access.
- Allow administrators to create, view, edit, activate, deactivate, and search users.
- Manage roles, permissions, organisational access, and privileged actions using least-privilege defaults.
- Display account status, assigned role, last login, and access history.

### 12. Audit Logs and System Settings Page

- Display searchable audit logs for authentication, data access, record creation, modification, deletion, export, AI execution, approval, rejection, override, and configuration changes.
- Provide filters for user, role, action, entity, date, outcome, and relevant organisational scope.
- Allow administrators to configure master data, workflow rules, thresholds, AI settings, integrations, and notification rules required by this project.
- Prevent normal users from modifying or deleting audit records.

### Requirements for Every Output Page

- Use responsive layouts for desktop, tablet, and mobile devices.
- Include consistent navigation, page titles, breadcrumbs, loading indicators, empty states, validation messages, error states, and success feedback.
- Apply role-based access control to page visibility, data, and actions.
- Include global search, filtering, sorting, pagination, saved views, notifications, and export where appropriate.
- Use realistic sample data and connect displayed information to backend APIs and the selected database.
- Show AI outputs with confidence, concise evidence-based explanations, timestamps, model/version details, and authorised review controls.
- Do not expose the Gemini API key or any other secret in frontend code.
